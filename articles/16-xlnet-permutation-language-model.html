XLNet：排列分解怎样获得双向上下文，却不泄漏答案

同一句话，换一种预测顺序就能看到不同的上下文。关键是让模型知道“要猜哪里”，同时永远不把“被猜的词”直接交给它。

阅读约 28 分钟主题：Permutation LM / Two-Stream核心问题：目标信息如何隔离

1. 从“下一个词”只能看左边开始

传统从左到右的自回归语言模型把一句话分解成一连串条件概率：预测第 t 个词时只能使用左边的已知词。它很适合逐词生成，却让预训练中的同一位置无法直接依赖右侧上下文。BERT 的 Masked Language Modeling（MLM）采用另一条路线：同时暴露双向上下文，遮住部分 token 再恢复原词；但被预测 token 之间的联合依赖在基本 MLM 目标中并未以自回归方式显式展开。

XLNet 的想法不是简单“把句子反过来再训练一次”，而是给同一组原位置选择多种概率分解顺序，让某个位置有时先预测，有时最后预测。这样，一个位置在不同训练样本和不同分解顺序下可以利用来自其左边或右边的其他词，同时仍保持逐项条件概率的自回归形式。

2. 排列的是分解次序，而不是把词打乱读

令原文本的 token ID 为 x₁…xₜ。排列 z=(z₁,…,zₜ) 是原始位置索引的一个置换。在 z=(3,1,4,2) 时，训练因子依次预测原位置 3、1、4、2 对应的词；模型仍保留原始位置编码，例如位置 3 和位置 1 在自然句子中的关系不会因排列而改变。

对目标位置 zₜ，上下文来自排列中早于它的原位置，而不是“小于它”的文本坐标。因而原位置 2 既可能看见位置 1，也可能看见位置 3 与 4。有限训练仅抽样一部分排列，不会遍历指数级的所有组合；原论文还采用部分预测机制，只在排列的后段位置计算预测损失，以降低代价。

把排列语言模型误译成“随机把单词洗牌后让模型复原句子”会误导：词的身份与原始绝对/相对位置信息并没有因为抽样排列而失效；变化的是 attention mask 所编码的可用条件集合。

3. 数学上究竟优化什么

在任意预测次序 z 下，联合概率仍能用链式法则写出；训练平均不同排列下的对数条件似然。下面以四个位置、从头到尾均预测的概念版本说明分解，实际 XLNet 实现常只取排列的后一部分作为预测目标。

ℒPLM=𝔼z∼𝒵T[∑t=1Tlogpθ(xzt|xz<t)]

式中 𝒵ₜ 是位置排列的集合，x_z<t 表示排列前缀对应的 token。若词表大小为 V，预测目标的隐状态形状为 [B,T_target,H]，词表输出为 [B,T_target,V]；交叉熵只统计被指定为目标的位置，不能把未被预测的位置也虚构成具有标签损失。

与 BERT 的 MLM 相比，XLNet 在预测后续目标时能够利用先前已预测目标的真词内容。这个优势有条件：训练的 attention mask 必须严格禁止模型在预测某位置的同一时刻看到那个位置的词内容，否则目标变成抄答案。

4. 一条流不够：content 与 query 的边界

单条隐状态流会陷入悖论：如果位置 i 的表示读取了自己的词 xᵢ，它就可以作为其他位置的条件；但把同一个表示交给该位置的预测头，就有直接读取目标答案的风险。XLNet 让位置拥有两类不同状态。

Content stream 的状态 hᵢ 可吸收本位置 token 的内容，用于为以后排列位置提供 key/value；其可见集合包含排列前缀和当前自身。Query stream 的状态 gᵢ 代表“现在要预测原位置 i”，它知道目标位置相关信息，却不能获得 xᵢ 的内容；其 key/value 只能读取排列中已经允许的 content stream 状态。两条流不是两个独立语言模型；它们分享 Transformer 参数，但 attention mask 与 query 输入不同。

gzt(m)←Attention(Q=gzt(m−1),KV=hz<t(m−1))

上式是核心依赖关系的简写，而非包含残差、层归一化、相对位置项的完整 Transformer-XL block。特别注意：Query stream 并非“不知道目标在哪里”；若连目标位置都不携带，同一个上下文将无法区分“预测哪个槽位”。它禁止的是目标词身份泄漏。

5. 具体算一次 attention 可见性

以四词 the chef cooked dinner 为例，原位置按 1–4 编号。排列 z=(3,1,4,2)，当预测原位置 2 的 chef 时，合法上下文位置为 {3,1,4}，即 cooked / the / dinner。Query stream 的该行 mask 允许访问这些 content states，但必须排除位置 2。

假设单头 Q∈ℝ[B,1,dₕ]，前缀的 K,V∈ℝ[B,3,dₕ]，attention score 为 [B,1,3]。当实现为了高效而用完整长度的张量 [B,T,H] 运算时，依赖关系由布尔/加性 mask 保证，而不是简单将所有不可见位置删出张量。

对于 content stream，位置 2 的 query 在自己已作为内容参加后续因子时可访问本位置内容；它的 hidden state 不能被误用为预测自己这一因子的 query，否则目标 token 会通过 residual/self-attention 等路径流回 logits。

6. Transformer-XL 记忆属于另一维设计

论文把排列预测和 Transformer-XL 的 segment recurrence、相对位置建模结合起来。缓存之前片段的隐藏状态为后续片段提供更长上下文，属于序列长度/跨 segment 机制，而非排列预测本身天然自带的能力。缓存的梯度截断、不同长度的 mask 和训练/评测配置需要依实现核实。

因此，“XLNet 是 BERT 换一种 MLM 方式”不精确：其核心是自回归排列分解与两流注意力；它在工程上还借用了 Transformer-XL，并非直接保留标准 BERT Encoder 结构与损失。

7. 解释实验时，不要从表格直接推导普适胜负

原论文在自然语言理解任务上报告强于当时 BERT 基线的结果，涉及训练数据、模型容量、优化、任务头与其他差别。对“PLM 一定优于 MLM”的因果判断，至少需要控制总训练算力、预训练语料、目标预测比例、tokenizer、下游搜索与重复试验。XLNet 自身的两流计算、排列采样、部分预测与记忆管理也增加实现复杂度。

推理阶段常使用 content stream 生成序列表示；训练时依目标预测而启用的 query stream 不能理解为所有下游任务都必须保留相同的两流预测接口。部署前应核对官方 checkpoint 对应模型的分类/问答 forward 定义。

关键结论

  • 置换作用于概率分解次序，不是随机打乱文本坐标；不同条件集合让目标得以看见左右两侧内容。
  • Query stream 必须排除当前目标的词身份；Content stream 可以保存已允许词的内容以供后续因子使用。
  • Transformer-XL 记忆、相对位置、部分预测是原始方案的工程组成，不能与 PLM 概念本身混为一谈。
  • 改动目标函数与训练成本时，应做受控比较而不是从单张任务表推出普适优劣。
